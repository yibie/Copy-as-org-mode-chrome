* Copy as Org-Mode — Chrome Extension

Convert web content to [[https://orgmode.org/][Org-mode]] format with one click.  
A Chrome port of [[https://addons.mozilla.org/en-US/firefox/addon/copy-as-org-mode/][Copy as Org-Mode for Firefox]] by [[https://github.com/kuanyui][kuanyui]].

** What It Does

This extension turns any web page into clean [[https://orgmode.org/][Org-mode]] text — the markup
language used by Emacs Org-mode, [[https://logseq.com/][Logseq]], and many note‑taking tools.

You trigger it from the right‑click context menu. Five operations:

| Menu Item | Action | Output |
|-----------+--------+--------|
| *Copy Selection as Org-Mode* | Select text on a page, right‑click → copy | Org-mode formatted text in clipboard |
| *Save Page as Org-Mode* | Right‑click anywhere on the page | =.org= file downloaded |
| *Save Page as Org-Mode (With Images)* | Right‑click anywhere on the page | =.org= file + all images saved to a folder |
| *Copy Link as Org-Mode* | Right‑click a hyperlink | =[[url][text]]= in clipboard |
| *Copy Page URL as Org-Mode Link* | Right‑click the page background | =[[url][title]]= in clipboard |

A keyboard shortcut (~Ctrl+Alt+O~) is also available for "Copy Selection".

** Reader View with Highlights

Read the article without clutter, mark what matters while you read, and
export it as Org text where your highlights are already [[https://github.com/yibie/org-zettel-ref-mode][chai]] links —
so you do not read the page a second time in Emacs to mark it up.

*Open and close*: right‑click → *Reader View*, or bind =toggle-reader-mode=
at =chrome://extensions/shortcuts=. Exit with ✕, Esc, or the same shortcut.
The Reader opens over the page with a short fade; the page underneath is
not touched, so closing it leaves your scroll position, forms and video
where they were (no reload).

*Highlight*: select text in the Reader, then pick a type in the menu that
appears. You can add a note first; it shows as a bubble above the
highlight. Click a highlight to change its type or note, or to remove it.

*Export*: the toolbar's Org menu has *Copy as Org-Mode*, *Save as Org-Mode*
and *Save as Org-Mode (with images)*. Highlights come out in chai's syntax:

: [[chai:key][highlighted text]]
: [[chai:question:my note][highlighted text]]

A highlight that spans paragraphs becomes a block:

: #+BEGIN_CHAI :type key :note "my note"
: first paragraph ...
: second paragraph ...
: #+END_CHAI

Brackets in the text and note are escaped the way Org's own
=org-link-make-string= does it, so chai reads every link back intact.

*Types*: the menu lists the types from Options → *Reader Highlights (chai)*.
The defaults are =key=, =idea=, =question= and =fact=; add, remove, rename,
reorder or recolor them there. Use the same names as =chai-highlight-types=
in Emacs. A type chai does not know still exports; chai shows it as a plain
link.

*Limits*:
- Highlights live only while the Reader is open. If you changed highlights
  since the last Copy or Save, exiting asks you first.
- Selections that include images, tables, code blocks or video, overlap an
  existing highlight, or cross into a list item cannot be highlighted.
- Images in the Reader load from the extension page, so a site that blocks
  hotlinking may not show some images. Saving with images is not affected.

** Intelligent Content Extraction

This is the most important feature. When you save a page, the extension does
*not* dump raw HTML into your Org file. Instead, it uses [[https://defuddle.md][Defuddle]] v0.19 to
intelligently extract the *real content* — stripping ads, sidebars, comments,
navigation, and other clutter.

Defuddle goes further than traditional readability tools. It has built‑in
knowledge of 26+ websites and knows how to pull content from each one
correctly — including content that isn't even visible on the page.

*** YouTube (the killer feature)

When you save a YouTube video page, Defuddle:

1. Extracts the video title, description, channel name, and upload date
2. Embeds an =iframe= of the video in the Org file
3. **Fetches the full transcript** with timestamps via YouTube's InnerTube API
4. Groups sentences by speaker turns (auto‑detects ">>" speaker markers)
5. Adds chapter markers from the video's chapter list

The transcript appears as structured Org‑mode text below the video embed, with
timestamp links like:

: **0:12 · Today we're going to talk about...

: **5:47 · The first thing we need to understand is...

The transcript language is configurable (see [[#settings][Settings]] below).

*** Supported site extractors

Defuddle has specialized extractors for these sites. When you save one of
them, you get clean, site‑structured output instead of raw DOM HTML.

**Video**
| Site      | What gets extracted                                          |
|-----------+--------------------------------------------------------------|
| YouTube   | Title, channel, description, embed, **transcript**, chapters |
| Bilibili  | Video info, description, comments                             |

**Conversation / AI Chat**
| Site     | What gets extracted            |
|----------+--------------------------------|
| ChatGPT  | Clean conversation thread      |
| Claude   | Clean conversation thread      |
| Gemini   | Clean conversation thread      |
| Grok     | Clean conversation thread      |
| Google AI Mode | Each turn as a question heading + answer, without the page's buttons, panels and account info |

**Social Media**
| Site       | What gets extracted                                       |
|------------+-----------------------------------------------------------|
| Twitter / X| Tweets with structured metadata, X Articles               |
| Reddit     | Post + threaded comment tree with depth                   |
| Hacker News| Post + threaded comment tree                              |
| LinkedIn   | Posts                                                      |
| Bluesky    | Posts                                                      |
| Mastodon   | Posts                                                      |
| Threads    | Posts                                                      |

**Forums & Discussion**
| Site       | What gets extracted            |
|------------+--------------------------------|
| Discourse  | Clean thread with replies      |
| LWN.net    | Linux kernel news article      |

**Articles & Publishing**
| Site        | What gets extracted            |
+-------------+--------------------------------+
| Wikipedia   | Full article text               |
| Medium      | Clean blog post                 |
| Substack    | Newsletter post                 |
| NY Times    | News article (behind paywall OK)|
| GitHub      | README, Issues, PRs             |
| LeetCode    | Problem description + examples  |
| C2 Wiki     | Wiki page text                  |
| Zhihu (知乎专栏) | Article body, author, date, original images; no vote counts, search links or redirect links |

When none of the above match, Defuddle falls back to its general‑purpose
content extraction algorithm — which is significantly more aggressive at
removing clutter than Mozilla's Readability. The result is a cleaner, more
focused Org file in every case.

*** "Save Page" output includes

Every saved page includes an Org‑mode header block:

: #+TITLE: Page Title
: #+DATE: 2026-06-23T...
: #+AUTHOR: Author Name
: #+SOURCE_URL: https://...
: #+KEYWORDS: keyword, tag

Plus an intelligently named file:

: Author__Title==keyword1_keyword2.org

** Settings

Open the extension options page (right‑click the extension icon → Options).

| Setting | Description |
|---------+-------------|
| *Language for Transcriptions & Extraction* | BCP 47 language code (e.g. =zh-Hans=, =en=, =fr=) used by YouTube to select subtitle tracks and by Defuddle to set =Accept-Language= headers for extractors. Leave empty for automatic detection. |
| List indent size, bullet style, code style | Customize Org-mode output syntax |
| Reference link format | Template for source page references (=%title%=, =%url%=, =%date%= tokens) |
| Notification style | In‑page toast notification vs. system notification |
| Image path prefix | How image paths are written in the Org file (e.g. =./images/=) |

** How to Save a Page with Images

The "Save Page as Org-Mode (With Images)" option downloads all page images to
a folder alongside the Org file:

1. Right‑click → *Save Page as Org-Mode (With Images)*
2. A new tab opens → click *Select Folder & Save*
3. Pick any folder (e.g. =~/Documents/Notes=)
4. Grant file‑edit permission when the browser prompts you
5. Done — the =.org= file creates an =images/= subfolder automatically

*** Brave users

Brave disables the File System Access API by default. To enable it:

: brave://flags → search "File System Access API" → Enabled

If unavailable, the extension falls back to downloading a ZIP file containing
both the Org file and the images folder.

** Installation

1. Download =copy-as-org-mode-v1.6.0.zip= from the [[https://github.com/yibie/Copy-as-org-mode-chrome/releases][Releases page]].
2. Unzip it.
3. Open Chrome → go to =chrome://extensions=.
4. Enable *Developer mode* (toggle in the top‑right).
5. Click *Load unpacked* → select the unzipped folder.

Or clone the repo and build:

: git clone https://github.com/yibie/Copy-as-org-mode-chrome
: cd Copy-as-org-mode-chrome
: npm install
: npm run build

Then load the =dist/= directory as an unpacked extension.
